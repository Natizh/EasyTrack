# Transaction export (Issue #1)

**Settings → Export transactions** writes ordinary CSV or XLSX transaction files through the native Files exporter. Activity also offers **Export filtered transactions**. These files are separate from the version-6 JSON backup: they contain no raw notification captures, parser attempts, rule JSON, or bulk spreadsheet source rows. The app performs no network request during export.

## Approved choices

The [Issue #1 decisions](https://github.com/Natizh/EasyTrack/issues/1) are: readable Basic columns by default; extra historical fields under Detailed; source/technical IDs under a separate opt-in; interoperable CSV by default, with Italian Excel as another preset; kind and positive current amount retained beside an additional signed directional EUR amount; and **intersection** of current Activity filters with dedicated export filters. Conflicting filters intentionally yield a header-only file. Settings export starts without Activity filters.

## Selection and values

One read-only SQLite connection opens the existing schema-5 database, starts a read transaction, and reads transactions, account/category names, trip names, and decoded historical provenance from one consistent snapshot. It rejects unreadable transactions. Export neither calls the normal write/migration initializer nor updates operation logs. Deleted and Demo transactions are excluded. Rows sort by occurrence timestamp, then stable UUID. Files from both serializers use the same immutable selected rows.

The export screen supports all time, current/previous month, current/previous year, and custom **inclusive local dates** in the device time zone captured for that export. Around daylight-saving transitions, selection compares local calendar dates rather than fixed 24-hour windows. Account and category choices use managed stable IDs where present, including archived references and renamed names; legacy labels remain separate rather than being guessed into an ID. Uncategorized is an explicit category choice. Accounts, categories, kinds, trips and currencies accept multiple selections. Text matching covers description, note, account/category names, payer, trip and kind.

Basic columns are occurrence date/time, description, kind, displayed account and category, **current stored** positive amount and its currency, current EUR amount when known, personal spending EUR, recoverable EUR, signed directional EUR, and note. Detailed adds subcategory, trip, payer, affects-accounts flag, historical exchange rate, and **original imported** amount/currency/EUR/timestamp decoded from preserved import provenance. The optional technical set adds stable IDs and source sheet/row. Blank means missing, while `0.00` means a stored zero. No exchange rate or account link is inferred. A movement edited from THB to EUR therefore keeps the current edited EUR amount separate from its imported THB values.

The kind and stored amount remain explicit and positive. Signed directional EUR is negative for expense, PAC, advance, and deposit; it is positive for income, reimbursement and deposit refund. Personal spending EUR uses the ledger's stored signed personal value, including a reimbursement adjustment; it is **not** the signed directional amount. Summary expense totals include `expense` only, income includes `income` only, and PAC has its own total. Other kinds do not get relabeled as expense or income. Rows lacking a known EUR amount leave EUR cells blank; summary totals treat that missing EUR as zero without inventing a conversion. Checked integer-cent accumulation rejects overflow.

## File formats and limits

CSV follows [RFC 4180 escaping and CRLF records](https://www.rfc-editor.org/rfc/rfc4180). The interoperable preset uses UTF-8, a comma and decimal dot without a BOM; the Italian Excel preset uses a semicolon, decimal comma, and UTF-8 BOM. Dates are ISO 8601 with time-zone offset. Every text cell is quoted; embedded quotes are doubled. Text whose first non-whitespace/control character is `=`, `+`, `-`, or `@` receives a leading tab **inside the quoted field** to reduce spreadsheet formula interpretation, following [OWASP's CSV injection guidance](https://owasp.org/www-community/attacks/CSV_Injection). Consumers that remove that prefix and then reopen the file can reintroduce the risk.

XLSX is a genuine [ECMA-376 Office Open XML](https://www.ecma-international.org/publications-and-standards/standards/ecma-376/) workbook packaged in a standards-compliant ZIP using uncompressed entries. It uses inline text cells, numeric amount cells, numeric local-wall-clock Excel date cells with date styles, currency styles for EUR, readable widths, a frozen `Movimenti` header, and an autofilter. Inline text prevents untrusted descriptions from becoming formulas. Optional `Riepilogo` contains selected-row count; personal, expense, income and PAC totals; and category, account and month groups that each reconcile to those totals. XLSX has no app runtime dependency. ZIP storage is uncompressed to keep the writer small and deterministic. Excel's numeric cells have a 15-significant-digit precision limit; XLSX export rejects an amount beyond that limit rather than silently lose cents. CSV remains exact for valid stored `Int64` cent amounts.

Excel dates do not carry time-zone metadata. XLSX stores the selected time zone's local wall clock as a numeric serial; CSV retains the explicit offset. Filtering and summary month groups use the same local time zone.

## Verification

Run `sh scripts/test_transaction_export.sh` to generate fictional files under ignored `DerivedData` and run the focused Swift and independent file checks. Swift tests cover all seven kinds, personal shares, recoverables, PAC, reimbursements, missing EUR, historical/edit distinction, stable archived IDs, DST and inclusive dates, combined/Activity filters, empty exports, Unicode, quotes, formula prefixes, deleted/Demo exclusion, large histories, read-only SQLite snapshots and CSV/XLSX consistency. `scripts/validate_transaction_export.py` independently parses those files with Python's `csv`, `zipfile`, and XML libraries; when installed locally it also opens XLSX with `openpyxl`. The test-only `openpyxl` installation is under ignored `DerivedData` and is not an application or package dependency.

Simulator Files tests use only the isolated iOS 27 iPhone 17e and fictional records. They verify CSV and XLSX saving, optional summary, Activity filter handoff, persistence and read-only database integrity. No physical iPhone, third-party Files provider, or spoken VoiceOver session has been tested; those remain in [Issue #8](https://github.com/Natizh/EasyTrack/issues/8).
